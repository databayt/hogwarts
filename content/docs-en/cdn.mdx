Every curated hogwarts asset lives under the `hogwarts/` namespace of `cdn.databayt.org` (hogwarts is the internal name; balqalam is only the public brand). There are two tiers:

1. **Product media** — the stills and videos `/shoot` and `/record` produce. The path **mirrors the app's URL, language first**, file names are fixed and never hashed, and pages and the support chat read them by id from `src/components/docs/media-manifest.json`, never by URL.
2. **App chrome** — icons, illustrations, animations and photos, through `asset()` (flat, unhashed).

Chrome is cached `immutable` for one year; product media is overwritten in place on a re-shoot (an hour in browsers, a year at the edge, invalidated on overwrite) and its manifest URLs carry `?v=<sha8>`. One origin helper, `src/lib/cdn.ts` (`CDN_ORIGIN`, `cdn(key)`), builds every URL; nothing else hard-codes the domain.

## Product media — the CDN mirrors the app URL

```
<school>.databayt.org/<lang>/<route>
cdn.databayt.org/hogwarts/<lang>/<route>[/<flow>]/<asset>
```

Route groups and `s/[subdomain]` never reach a URL, so they never reach a key. When one route hosts two flows (`/school/bulk` imports students and teachers) each gets a short subfolder. Every key names its language; English is the same path under `en/`.

| Asset       | Key                                                                 |
| ----------- | ------------------------------------------------------------------- |
| Tutorial    | `video.mp4` · `video.av1.mp4` · `video.poster.webp` · `video.vtt`   |
| Still       | `<step>.avif` · `<step>@2x.avif` · `<step>.webp` · `<step>@2x.webp` |
| Phone still | `iphone-16/<step>.avif`                                             |
| Reel, clip  | `reel.mp4` · `<clip>.mp4`                                           |
| Page still  | `page.avif` (home → `hogwarts/<lang>/page.avif`)                    |

| Flow           | App route       | CDN folder                         |
| -------------- | --------------- | ---------------------------------- |
| add-student    | `/students`     | `hogwarts/ar/students/add/`        |
| add-teacher    | `/teachers/add` | `hogwarts/ar/teachers/add/`        |
| bulk-student   | `/school/bulk`  | `hogwarts/ar/school/bulk/student/` |
| bulk-teacher   | `/school/bulk`  | `hogwarts/ar/school/bulk/teacher/` |
| set-fees       | `/finance/fees` | `hogwarts/ar/finance/fees/`        |
| view-timetable | `/timetable`    | `hogwarts/ar/timetable/`           |

So `cdn.databayt.org/hogwarts/ar/school/bulk/student/video.mp4` is the Arabic bulk-import tutorial, and `…/en/school/bulk/student/review.avif` its English review step. A re-shoot overwrites the same key; the manifest's `?v=<sha8>` makes browsers fetch the new bytes. A flow declares its folder as `export const route` in kun's `shoot/flows/hogwarts/<flow>.mjs`; `media.sh prune` lists keys nothing serves any more.

Render them by manifest id:

```mdx
<FlowMedia flow="add-student" />
<Shot id="add-student/created-ar" />
<TutorialVideo id="add-student/video-ar" />
```

`FlowMedia` lists stills by their `order` (the step number they were shot in). The sources stay outside the repo in `~/media/hogwarts/<flow>/`; see the kun `shoot` docs for the full grammar.

## App chrome — `asset()`

```tsx
import { asset } from "@/lib/asset-url"

<Image src={asset("/icons/logo.png")} />
<Image src={asset("/illustrations/attendance.png")} />
<img src={asset("/icons/visa.svg")} />
<source src={asset("/media/story.mp4")} />
```

`asset("/icons/logo.png")` → `https://cdn.databayt.org/hogwarts/logo.png` — only the file name is kept.

## Adding new assets

Product media (screens, flows, videos): shoot or record it, then `publish.mjs --flow <flow>` — never upload by hand.

App chrome:

1. Upload to `hogwarts/<file>`.
2. kebab-case, lowercase filenames.
3. Set `Content-Type` and `CacheControl: "public, max-age=31536000, immutable"`.
4. Reference with `asset("/category/filename.ext")`.

Or use the migration script.

```bash
pnpm tsx scripts/migrate-assets-to-s3.ts            # dry run
pnpm tsx scripts/migrate-assets-to-s3.ts --upload   # upload
pnpm tsx scripts/migrate-assets-to-s3.ts --manifest # output JSON manifest
```
